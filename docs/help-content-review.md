# Help content review

Reviewed on 17 October 2026 against the current conversion tool code. The category/article layout is retained. Guide-specific copy, requirements, FAQs, links, draft notes and screenshot slots are stored in `src/helpContent.ts`.

## Checked behaviour

| Subject | Confirmed behaviour and documentation adjustment | Evidence |
| --- | --- | --- |
| Upload requirements | No single upload field is mandatory. Check files requires a selection; invoice rows require at least one supported invoice CSV. The main field is **Removal invoices CSV**, with separate **Removal deposits CSV**, **Ad Hoc invoices CSV** and **Credit notes CSV** fields. CSVs contain tax, nominal and account reference information. | `uploadPage`, `uploadSlots`, Check files handler and `parseCsvFiles` in `functions/[[path]].ts`; `src/removalsParser.ts` |
| Monthly report | **Monthly invoice report PDF** is optional but recommended for customer names, services and comparing totals/VAT. It needs readable PDF text and an invoice CSV for reconciliation. Service descriptions can help identify deposits; review is still required. | `parseCsvFiles`, `extractPdfText`; `src/monthlyReportParser.ts`, `src/reconciliation.ts`, `src/classification.ts` |
| Customer CSV and addresses | No customer CSV field or customer CSV parser exists. Labelled **Not supported by this tool**, rather than suggesting an optional address import. Customer matching uses Sage contacts; explicitly created contacts use TEST address details. Complete those details in Sage. | `uploadSlots`, `renderCustomerMappings`, `createPlaceholderContact`; `src/sage.ts` |
| Other files and limits | Individual invoice PDFs accept multiple files but receive type/size checks only; they do not supply invoice data. Each other field takes one file. Files must be non-empty, at most 20 MB, and have the corresponding CSV/PDF extension and accepted type. Credit notes can be reviewed; no Sage credit-note creation is provided. | `validateFile`, `parseCsvFiles`; `src/sageDraftInvoice.ts`; README MVP notes |
| Review and saving | Correct label is **Save reviewed batch**. Review decisions can be changed before saving; invoice amounts/dates/descriptions are not edited in the review table. Saved rows are locked. There is no saved-batch browser or general reopen/edit screen. A matching re-upload can reconnect a saved batch and refresh eligible metadata; this is not general batch editing. | `saveBatchButton` handler, `reviewActionSelect`, `handleImportBatchSave`; `refreshPreviouslySavedInvoices` in `src/db.ts` |
| Sage setup | **Set up Sage conversion**, **VAT conversion**, **Nominal code conversion**, **Customer matching**, **Save VAT choice**, **Save category choice**, **Search Sage contacts**, **Save contact** and **Change contact** are actual labels. Suggestions need confirmation. **Create with TEST details** is an explicit, confirmed customer-creation action. | `uploadPage`, reference mapping renderers and `renderCustomerMappings` |
| Draft invoices | Requires a saved reviewed batch, ready invoices and confirmed mappings. **Check selected draft details** includes the selected count. Creation requires a checkbox and confirmation prompt; the Create button also includes the count. Due dates can be changed before rechecking. The payload requests `DRAFT`; no sending, releasing, publishing or credit-note creation is performed. Uncertain results must be checked in Sage before retrying. | `updateDraftSelectionControls`, `previewSelectedDraftInvoices`, `createSelectedDraftInvoices`; `src/sageDraftInvoice.ts`, `src/sage.ts` |

## Still unverified

- No live Removals Manager session or independently verified product instructions were available. All three supplied export guides remain visibly **Draft guide — for review**. Their supplied menu paths, date controls, report-generation actions, new-tab behaviour and file-saving methods must be checked in the user's version of Removals Manager before publication as confirmed instructions.
- Check that **Generate Sage CSV File** produces the invoice format accepted by this tool. Do not assume a customer CSV can be uploaded in an invoice field.
- Check the customer CSV's contents, especially addresses, and its date controls. Step 6, **Save the CSV file**, has `status: "to-be-confirmed"` and an explicit review note. Its proposed download wording is not presented as a confirmed workflow.
- The FAQ about reporting dates describes using new source exports; the exact Removals Manager From/To procedure remains draft. The conversion tool has no reporting-range filter for an existing upload.
- Every individual step reserves an optional screenshot with `screenshot: null`. No screenshots have been invented. Add approved screenshots only after verifying the steps and removing private customer information.

The supplied wording is retained where supported. Adjustments above correct unsupported customer-address imports, individual PDF parsing, saved-batch editing and automatic approval/sending implications. Existing guide IDs are retained for corresponding topics, with new IDs for the customer export and FAQs. No conversion, calculation, authentication or Sage integration behaviour was changed.
